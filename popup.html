Best & Robust Step Writing Guide
Follow these rules so every step runs without fail
1. Always name the section when multiple similar elements exist

If the page has several cards/buttons with the same label (e.g. multiple "Continue" buttons), tell the executor which section the element is in. The executor will find that section first, then the button/link inside it.

  • Use: Click the Continue button from the FracPro Live+ card
  • Use: Click Submit in the Login section
  • Avoid: Click Continue (ambiguous when there are many)

Phrases that work: from the … card, in the … section, on the … panel, within the … form.

2. Start the step with a clear action verb
  • Click: Click, Press, Tap, Submit — e.g. Click the Login button
  • Type: Enter, Type, Input, Fill in, Write — e.g. Enter username in username field. Put the value in TestData.
  • Verify: Verify, Validate, Check, Assert — e.g. Verify the dashboard title is displayed. Put expected text in ExpectedResult.
  • Navigate: Navigate to, Open URL, Go to — e.g. Navigate to https://app.example.com. URL can be in step or TestData.
3. Use the exact text that appears on the page

Button labels, section titles, and link text should match the UI (case-insensitive). E.g. if the button says "Sign in", write Click the Sign in button or Click Sign in.

4. Put input values in TestData

For type/enter steps, keep the step description short and put the value to type in the TestData column: e.g. Step = Enter email in email field, TestData = user@example.com.

5. Use ExpectedResult for verification steps

For verify/check steps, put the expected text or condition in ExpectedResult. E.g. Step = Verify welcome message, ExpectedResult = Welcome, Admin.
